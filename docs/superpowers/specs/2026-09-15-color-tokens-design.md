# 색 토큰 · 다크 모드 · 컬러 바 — 설계

팔레트 생성기가 뽑은 색 토큰을 사이트에 들이고, 다크 모드를 켜고, 화면 구석에
그 토큰을 실제로 찍는 컬러 바를 세운다. 이력서에 디자인 시스템 항목을 추가해
컬러 바가 그리로 간다.

확정된 팔레트:

```
https://haneulcha.github.io/design-system-starter/color-palette?v=1&a=fa862e&n=green-soft&t=7-&ts=8-
```

액센트 `#fa862e`(주황, H 52.6°), 뉴트럴 그린 그레이(세이지), 대비 보정 2건 적용.

관련 문서: [① Tailwind 전면 교체 설계](2026-09-15-tailwind-migration-design.md) —
이 스펙은 그 후속이다.

## ①과 정반대의 합격 기준

①은 "픽셀이 안 움직여야" 성공이었고 기준선 PNG 재생성을 금지했다. **이 스펙은
색이 바뀌는 게 성공 조건**이므로 기준선을 다시 뜬다. 다크가 붙으니 2장에서
**4장**이 된다 (`landing` · `about` × 라이트 · 다크).

①에서 배운 것 두 가지를 규칙으로 옮긴다.

**`maxDiffPixelRatio: 0.001`은 1280×2799에서 약 3,500픽셀을 봐준다.** 기준선을
재생성한 뒤의 "통과"는 정확성의 증거가 아니다 — ①에서 행간 회귀(19.2px→18px)가
그 안에 들어가 전에도 후에도 통과했다. 색 매핑은 스크린샷이 아니라 **표로 대조해**
확인한다.

**스크린샷이 못 보는 것을 손으로 본다.** 선택 하이라이트, `:hover`, 320/375px,
3상태 토글의 시스템 모드, `prefers-color-scheme` 변화 구독. ①에서 이 목록 중
둘을 놓쳐 최종 리뷰까지 갔다.

## 1. 토큰 도입 — 기존 변수 6개를 없앤다

`palette.theme.css`를 `src/styles/`에 두고 `global.css`에서 import한다.
**생성물이므로 손대지 않는다** — 팔레트를 다시 뽑으면 편집이 날아간다.

기존 CSS 변수 6개는 **별칭으로 남기지 않고 지운다.** 별칭을 두면 이름 체계가 둘이
되어 "디자인 시스템을 보여준다"는 목적이 무색해지고, 다음 사람이 어느 쪽을 써야
할지 알 수 없다.

| 기존 변수                   | 값        | 새 토큰                 | 라이트          | 다크            |
| --------------------------- | --------- | ----------------------- | --------------- | --------------- |
| `--color`                   | `#24292f` | `neutral-text-strong`   | `#252825` (800) | `#d1d5d2` (300) |
| `--bg` (카드 배경)          | `#fbfcff` | `neutral-subtle-bg`     | `#fafafa` (50)  | `#070908` (950) |
| `--bg` (선택 글자)          | `#fbfcff` | `accent-on-solid`       | `#000000`       | `#000000`       |
| `--point-color` (링크·점)   | `#0550ae` | `accent-text`           | `#ae5500` (700) | `#ffa265` (400) |
| `--point-color` (선택 배경) | `#0550ae` | `accent-solid`          | `#fa862e` (500) | `#fa862e` (500) |
| `--point-color-hover`       | `#1678ef` | `accent-text-strong`    | `#8c4300` (800) | `#ffc49f` (300) |
| `--point-color-selection`   | `#3067ab` | **사라진다** (아래 2절) | —               | —               |
| `--border-color`            | `#e6e8e6` | `neutral-border`        | `#e4e7e5` (200) | `#252825` (800) |

바뀌는 자리는 `classes.ts`(`linkColor` `bodyP` `techLabel` `infoTableRow`),
`about.tsx`(셸·`h2` 점·문단), `JobSection.tsx`, `global.css`(`.resumeHtml a`)다.

**`on-solid`이 검정이다.** 계산 결과다 — 주황 `#fa862e` 위에서 흰 글자는 대비
2.47, 검정은 8.51이라 엔진이 검정을 고른다. 버튼과 선택 하이라이트의 글자가
흰색에서 검정으로 바뀐다. 팔레트가 주는 선택지가 아니라 밝은 주황을 고른 대가다.

## 2. 선택 하이라이트를 하나로 통일한다

현재 `/about`에는 선택 색이 **두 가지**다. 문단은 `--point-color`, 「기술 스택」
라벨은 `--point-color-selection`. 이건 의도된 디자인이 아니라 **CSS 상속 사고의
잔재**다 — 옛 `.main p::selection`이 `<p>`만 잡았고 라벨은 전역
`.aboutPage *::selection`으로 흘러내렸다. ①은 픽셀 충실도가 목표라 그 사고까지
보존했다.

②에서는 색이 바뀌는 게 허용되므로 **고친다.** `global.css`의 `@layer base`에
루트 `::selection` 하나만 두고 페이지 전체가 같은 색으로 선택된다.

```css
@layer base {
  ::selection {
    background: var(--color-accent-solid);
    color: var(--color-accent-on-solid);
  }
}
```

`@layer base`에 두는 이유는 유틸리티가 필요하면 이길 수 있어야 하기 때문이다 —
지금은 이기는 쪽이 없지만, 비레이어로 두면 나중에 누가 `selection:` 유틸리티를
붙였을 때 조용히 안 먹는다.

이 결정이 지우는 것:

- `bodyP`의 `selection:` 유틸리티 두 개
- `about.tsx` 두 자리의 인라인 `selection:` 유틸리티
- `techLabel`의 `selection:!bg-[var(--point-color-selection)]`과
  `selection:!text-[var(--bg)]` — **`!important` 해킹 전체**
- `global.css`의 `.aboutPage *::selection`
- 그에 딸린 전역 클래스 `aboutPage` 자체

①의 최종 리뷰가 파헤친 취약성 — Tailwind가 `selection:`을 `.foo::selection`과
자손 `.foo ::selection` 두 규칙으로 뱉고, 둘 사이 승자가 **문자열 정렬
타이브레이크**(`)` 0x29 < `-` 0x2D)로 갈리던 것 — 이 통일로 **원인째 사라진다.**
`!important`로 굳혀둔 것은 이 스펙까지 버티기 위한 임시방편이었고 여기서 역할을
다한다.

## 3. 다크 모드 — `.dark` 클래스 + 3상태

`generateColorThemeCss`가 `.dark` 선택자를 하드코딩한다 (`generateColorCss`와 달리
선택자 옵션이 없다). **그 계약을 그대로 받고**, `<html>`에 클래스를 붙이는 쪽을
우리가 맡는다. 생성 파일을 건드리지 않는 유일한 방법이다.

**상태는 셋이다.** `data-theme` 속성이 없으면 시스템, `light`, `dark`.
선택은 `localStorage`에 저장한다. 토글은 `시스템 ◐` → `라이트 ○` → `다크 ●` 순환.
텍스트를 남기는 건 아이콘만으로는 "지금 시스템을 따르는 중"이 안 보이기 때문이다.

**`<head>`에 인라인 블로킹 스크립트를 넣는다.** 첫 페인트 전에 `.dark`를
결정하지 않으면 다크 사용자가 흰 화면을 한 번 보고 깜빡인다. 프리렌더된 정적
HTML이라 서버가 정답을 알 수 없으므로 클라이언트에서 가장 먼저 실행돼야 한다.

**시스템 모드일 때 `prefers-color-scheme` 변화를 구독한다.** OS 설정을 바꾸면
새로고침 없이 따라와야 한다.

새로 정할 색은 **타이틀바 5개 + 창 테두리·그림자 2개**뿐이다. macOS 다크 창
크롬을 인용한다 (`#3a3a3c` → `#2c2c2e` 계열). **신호등 12개는 안 바뀐다** —
macOS가 두 테마에서 같은 색을 쓴다. 이 사실이 하드코딩 색 22개 중 12개를 그대로
살린다.

## 4. 컬러 바 — CSS 변수를 직접 그린다

```tsx
<i style={{ background: 'var(--color-accent-text)' }} />
```

hex를 박지 않는다. 그러면 띠가 **팔레트의 그림이 아니라 팔레트 그 자체**가 된다.
테마 전환에 JS가 필요 없고, 팔레트를 다시 뽑아도 띠가 자동으로 맞는다. 인쇄
컨트롤 스트립이 그 인쇄물이 실제로 쓴 잉크를 찍는 것과 같은 성질이다.

**여섯 칸** — 이 화면이 실제로 소비하는 역할만 찍는다.

| 칸     | 변수                  | 쓰이는 곳                  |
| ------ | --------------------- | -------------------------- |
| 여백   | `neutral-subtle-bg`   | 랜딩 배경, 창 안쪽         |
| 테두리 | `neutral-border`      | 이력서 표의 가로줄         |
| 본문   | `neutral-text-strong` | 이력서 본문                |
| 링크   | `accent-text`         | 링크, 소제목 점            |
| 솔리드 | `accent-solid`        | 버튼 배경, 선택 하이라이트 |
| 글자   | `accent-on-solid`     | 솔리드 위의 글자           |

호버하면 `getComputedStyle`로 실제 값을 읽어 역할명·hex·대비를 보여준다. 이
판독부만 JS가 필요하다 — 색 자체는 CSS가 그린다.

**배치는 대각선이다.** 컬러 바는 뷰포트 **우하단**, 테마 토글은 **우상단**. 서로
자리를 다투지 않는다.

`max-[1025px]`에서 `/about`의 창 여백이 `6vh auto` → `0 auto`로 바뀌어 창이 위쪽
끝에 붙는다. 그때 우상단 토글이 타이틀바 위에 얹히는데, 신호등 반대편이라 macOS
창 컨트롤처럼 읽혀 오히려 자연스럽다. 다만 **토글은 자기 표면(배경 + 테두리)을
가져야 한다** — 페이지 배경 위에서도 타이틀바 그라디언트 위에서도 읽혀야 하므로
투명 배경은 안 된다.

`src/components/ColorBar.tsx`와 `src/components/ThemeToggle.tsx`를 만들고
**`__root.tsx`에 둔다.** 두 라우트에 한 번에 붙고, 라우트별로 중복하지 않는다.
`about/` 아래가 아니라 `components/` 바로 아래인 것은 `/about` 전용이 아니기
때문이다.

## 5. 이력서 항목과 앵커

`resume.json`의 `portfolio` 맨 앞에 항목 하나를 넣는다. 기존 데이터 모양
(`title` `period` `url` `desc` `tech`)에 그대로 맞으므로 타입도 컴포넌트도 바뀌지
않는다.

초안 — **사용자가 검토하고 고친다.** 이력서 문구는 본인의 말이어야 한다.

| 필드     | 값                                                                                                                                                                                                                                                                                                  |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title`  | `design-system-starter`                                                                                                                                                                                                                                                                             |
| `period` | `2026. 4 ~`                                                                                                                                                                                                                                                                                         |
| `url`    | `https://github.com/haneulcha/design-system-starter`                                                                                                                                                                                                                                                |
| `desc`   | 디자인을 시작하기 위한 최소한의 결정이 무엇인지에 답하는 디자인 시스템 스타터. 실제 디자인 시스템 코퍼스를 분석해 기본값과 노브의 경계를 정하고, 색·타이포·간격·radius·elevation·컴포넌트 여섯 범주의 토큰과 AI 에이전트가 읽을 수 있는 `DESIGN.md`를 생성한다. **이 사이트의 색이 그 산출물이다.** |
| `tech`   | TypeScript, oklch, Tailwind v4, Figma MCP, Vitest                                                                                                                                                                                                                                                   |

`desc`에 링크를 넣으면 `dangerouslySetInnerHTML` 경로를 타므로 HTML 속성에
**작은따옴표**를 쓴다 (`<a href='...'>`). JSON 문자열 안이라 큰따옴표는
이스케이프가 필요하다 — 기존 관례를 따른다.

`PortfolioItem`이 `id`를 받아 `<section id="design-system">`을 낸다. 컬러 바는
`/about#design-system`으로 보낸다. 랜딩에서는 라우트 이동 + 앵커, `/about`에서는
같은 페이지 스크롤이다.

**`lastUpdatedAt`을 갱신한다.** 지금 `2022. 7. 23`인데 2026년 작업을 넣으면서
그대로 두면 앞뒤가 안 맞는다.

이력서 전면 갱신은 **범위 밖**이다. 경력이 2021년에서 멈춰 있고 포트폴리오가
2020년 항목 둘인 것은 이 스펙이 고칠 문제가 아니다 — 별건으로 다룬다.

## 6. 검증

```bash
pnpm type-check && pnpm lint && pnpm format:check && pnpm build && pnpm test
```

**기준선 4장을 재생성한다.** 다크 스크린샷은 Playwright가 `.dark` 클래스를 붙인
상태에서 찍는다 — `colorScheme` 에뮬레이션이 아니라 실제 토글 경로를 지나야 3상태
로직까지 검사된다.

**손으로 확인할 것** (자동 테스트가 못 본다):

- 문단·라벨·제목을 드래그해 선택 색이 **한 가지인지**
- 링크·신호등·요약의 `:hover`
- 320px·375px에서 표가 무너지는지 (두 테마 다)
- 토글 3순환과 **시스템 모드에서 OS 설정을 바꿨을 때** 따라오는지
- 새로고침 시 다크에서 흰 깜빡임이 없는지
- 좁은 화면에서 토글이 타이틀바 위에 얹혔을 때 읽히는지

**색 매핑은 표로 대조한다.** 위 1절의 표가 정본이고, 구현 후 실제 계산값이
그것과 일치하는지 브라우저에서 확인한다.

## 7. 하지 않는 것

- **타이포·간격 토큰화.** `/color-palette`는 색 전용이다. 타이포·간격 스케일은
  wizard의 산출물이고, 이 저장소의 기존 값은 **간격 13개 중 Tailwind 4px 그리드에
  떨어지는 게 0개**다. 토큰화한다는 것은 "이 숫자들이 틀렸다"고 결정하고 새로
  고르는 것 — 리팩터링이 아니라 디자인 변경이다. 별건으로 다룬다.
- **타이틀바·신호등의 라이트 색 토큰화.** macOS UI 인용이라 팔레트와 무관하다.
  다크 대응만 새로 정한다.
- **상태색 4개 스케일** (`error` `warning` `success` `info`). 이 사이트엔 폼도
  에러도 토스트도 없다. 팔레트가 변수는 내지만 쓰지 않는다.
- **이력서 전면 갱신**, OG 이미지, `sitemap.xml`, 브레이크포인트 변경.

## 8. 위험

- **`max-[Npx]:` N+1 패턴을 건드리지 마라.** Tailwind v4가 `width < N`(배타)으로
  컴파일하는 것을 상쇄한 값이다. `max-[1025px]` `max-[321px]` `max-[376px]`는
  의도된 숫자다.
- **`@layer base` 밖으로 리셋을 꺼내지 마라.** 비레이어 선언이 레이어 선언을
  특정도와 무관하게 이긴다. `tests/tailwind-setup.spec.ts`가 이 회귀를 잡는다.
- **`hover:`가 `@custom-variant`로 무가드 컴파일되고 있다.** ①에서 원본 CSS의
  semantics를 복원한 것이다. 다크 작업 중 되돌리지 마라.
- **`aboutPage` 클래스를 지우면 CLAUDE.md도 고쳐야 한다.** 2절의 선택 통일이 그
  클래스의 유일한 존재 이유를 없앤다.

## 9. 완료 후 CLAUDE.md 갱신

- CSS 변수 6개 목록 → 팔레트 토큰 체계
- `aboutPage` 문단 — 클래스가 사라지므로 삭제
- `.resumeHtml a`가 이제 토큰을 가리킨다는 사실
- 다크 모드 존재와 3상태 규약, 인라인 스크립트가 왜 필요한지
- 기준선이 4장이 됐다는 사실
- 기술 부채: "랜딩이 살아있는 위성을 안 가리킨다" — 컬러 바가 부분적으로 푼다
